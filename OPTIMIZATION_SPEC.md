# Спецификация извлечения контента Obeyscura

Базовый прогон завершён. Утверждён первый этап реализации общего конвертера с доступом к исходному HTML и отдельной оценкой правил сокращения.

## Цель

Увеличить количество проверяемой полезной информации на токен, переданный агенту. Эффект измеряется по сохранённым фактам, точности ответов и полной стоимости задачи с учётом повторных обращений. Экономия из-за ошибки загрузки, неполного выполнения JavaScript или пропуска фактов не засчитывается.

## Контракт

- Сохранять исходные формулировки, числа с единицами измерения, иерархию заголовков, структуру таблиц и списков, адреса ссылок, код, формулы, цитаты, сноски и доступные структурированные метаданные. Динамически загруженный контент оценивается в заранее заданной точке захвата.
- Хранить исходный захваченный HTML или DOM вне контекста модели. Обеспечить доступ к полному документу, отдельному разделу, таблице, исходному URL, цитате и исключённым блокам с указанием происхождения. Сырые данные ответа и сериализация DOM после выполнения JavaScript имеют разные точки захвата и маркируются явно.
- При достижении лимита сообщать о неполном результате и предоставлять способ продолжить чтение. Если используется лимит в токенах, указывать токенизатор и версию. Правила отбора и сериализации должны давать стабильный вывод для одного входа и набора параметров.
- Оптимизатор принимает сериализованный снимок, пригодный для одинаковой обработки после Obscura и Chromium. Основной алгоритм не требует вызова модели. Интеграция с MCP сохраняет действующее поведение существующих инструментов по умолчанию и рассматривает страницу как недоверенные данные.
- Полный HTML и полный Markdown служат режимами восстановления и сравнения. Очистка, компактный Markdown, адаптивное представление, структурированный JSON и дельты рассматриваются по результатам измерений. Выбор основного движка и условия fallback зависят от сравнения движков.

## Матрица сравнения

| ID | Движок | Представление |
| --- | --- | --- |
| A | Chromium + Playwright | Сериализованный DOM |
| B | Chromium + Playwright | Стандартный Markdown |
| C | Chromium + Playwright | Readability + тот же Markdown |
| D | Исходный Obscura | Встроенный Markdown |
| E | Chromium + Playwright | Общий оптимизатор |
| F | Obscura | Общий оптимизатор |

A–D образуют базовый прогон. Для сравнения снимков движков дополнительно прогоняется один и тот же стандартный конвертер на Chromium и Obscura. После реализации E и F получают снимки по той же политике готовности. Кандидата в Obscura измеряем также против D, чтобы улучшение относительно B не скрывало регрессию встроенного пути. Нагрузка и состав измеряемых этапов сопровождают результаты по времени.

## Данные и измерения

- Начальный набор состоит из 30–50 страниц с зафиксированными ожиданиями. Включаем документацию, репозитории, энциклопедии, статьи, магазины, форумы, SPA и страницы с таблицами, формулами, несколькими языками, кодом, вложенными списками, отложенной загрузкой, раскрываемым контентом и структурированными данными. Локальные страницы служат воспроизводимым корпусом. Живые сайты проверяют совместимость и учитываются в собственных прогонах. Набор для итоговой оценки выделяется до подбора алгоритма.
- На документах считаем токены каждого представления доступными токенизаторами, полноту размеченных фактов, сохранность критичных чисел и артефактов, доли ошибок загрузки и извлечения, время холодного запуска, захвата и обработки. Для ресурсов и конкурентности указываем охват процессов и единицы измерения. Неизмеренные показатели явно отмечаются.
- На согласованных агентских задачах измеряем входные, выходные, повторные и служебные токены, число вызовов и повторных загрузок, точность ответов, неподтверждённые утверждения, время и стоимость. Сравнение фиксирует модели, промпты, настройки и тарифы. Покрытие семейств GPT, Claude, Gemini, Qwen, DeepSeek и Llama зависит от доступности реального токенизатора или API подсчёта. Размер в байтах служит дополнительной метрикой.
- Каждый отчёт фиксирует версии браузеров, экстракторов и токенизаторов, коммит, ревизию корпуса, параметры запуска, операционную систему, оборудование и число повторов. Для сравнений используем одни страницы и политику готовности. Публикуем машинные результаты в JSON и CSV и краткое резюме в Markdown.

## Предварительные критерии приёмки

| Показатель | Цель |
| --- | ---: |
| Сокращение токенов относительно B на общем наборе успешно загруженных страниц | 20–50% |
| Полнота значимых фактов | ≥99% |
| Точность критичных чисел | 100% |
| Сохранность критичной информации | 100% |
| Молчаливое усечение и необратимая потеря захваченного контента | 0% |
| Регрессия точности ответов агента | 0 п. п. |

Знаменатель полноты включает эталонные факты соответствующих страниц. Отчёт показывает покрытие по всему корпусу и парное сравнение на общей выборке. Верхняя граница диапазона экономии служит ориентиром. Экономию принимаем, если она сохраняет точность и даёт выигрыш с учётом повторных запросов, общего времени и стоимости. Базовые измерения, исследование и утверждение плана предшествуют изменениям сервиса.
