# Извлечение контента в Obeyscura

Исходная ревизия `76db0c807f4bbaed062fcd3be7760adba49ac841`. Подробности реализации и ссылки на код собраны в [аудите](RESEARCH.md).

## Текущие границы

```text
HTTP → obscura-net → obscura-browser::Page → obscura-dom::DomTree
                            ↑                        ↕
                     obscura-js (V8) ← браузерные JS API
                            ↓
                        Markdown
                            ↓
                      CLI / CDP / MCP
```

`Page` обслуживает навигацию и жизненный цикл скриптов. HTML разбирается в Rust-дерево. JS читает и меняет его через нативные операции. Отрисовка лежит в `obscura-render` и подключается функцией `render`. Встроенный Markdown исполняется в том же V8 и доступен из CLI, CDP и MCP. Текст и AX-дерево имеют собственные пути. `browser_markdown` накладывает символьный лимит после сериализации, а `LP.getMarkdown` возвращает полный результат этого конвертера.

## Граница измерения и проектное направление

Оба движка передают снимок документа после зафиксированного условия готовности. Стандартный конвертер принимает одинаковый сериализованный HTML от обоих движков. Встроенный Markdown Obscura измеряется в той же сессии, из которой читается его снимок. Так можно сопоставить захваченные данные до конвертации и увидеть потери при сериализации.

Спецификация предлагает принимать снимок вида `{html, url, capture}` в общем оптимизаторе. Исходный снимок доступен отдельно, а представление для агента может ссылаться на стабильные разделы, таблицы и ссылки. Стратегия хранения, выбор библиотеки парсинга, формат идентификаторов и изменения MCP зависят от результатов эксперимента и утверждённого плана. Текущий контракт описан в [спецификации](OPTIMIZATION_SPEC.md).

## Первый утверждённый этап

Конвертер `obscura_dom::content::structured_markdown` принимает UTF-8 HTML-снимок и возвращает Markdown. Точка входа `obscura content` получает HTML через stdin или из файла. `fetch --dump structured-markdown` использует тот же конвертер на HTML после JavaScript. Для работы с исходником того же захвата сохраните `fetch --dump html` в файл, затем передайте файл в `obscura content`. Режим `obscura content --format html` выводит исходные байты.

Простые абзацы, заголовки и ссылки записываются Markdown. Секции с атрибутами сохраняют HTML-обёртку. Таблицы с объединёнными ячейками, MathML, вложенный код и раскрываемый контент сохраняют HTML-структуру. Для встроенного HTML используется список допустимых тегов, атрибутов и типов ссылок. JSON-LD выводится как данные с фиксированным типом. Исходный снимок остаётся доступным для сверки содержимого вне представления Markdown.
